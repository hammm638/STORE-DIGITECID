Dokumentasi API v1

Beli nomor virtual untuk OTP dan isi saldo lewat HTTP. Semua transaksi memakai saldo akun SHOP DIGITECID milikmu sendiri.

Mulai cepat

  1. Login ke situs, buka menu titik 3, pilih API dan dokumentasi, lalu buat API key.
  2. Isi saldo lewat menu Deposit di situs, atau lewat endpoint POST /deposits.
  3. Kirim permintaan dengan header X-API-Key.

Autentikasi

Kirim API key di setiap permintaan, kecuali /ping. Dua cara yang diterima:

X-API-Key: dtz_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Authorization: Bearer dtz_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Key hanya tampil sekali saat dibuat, server hanya menyimpan hash-nya. Jangan taruh key di kode front-end atau repositori publik. Membuat key baru langsung mematikan key lama. Kalau bocor, ganti segera.

Format respons

Semua respons berupa JSON. Sukses membawa ok: true dan isinya di data. Gagal membawa ok: false dan rincian di error.

{ "ok": true, "data": { "balance": 15000 } }

{ "ok": false, "error": { "code": "insufficient_balance", "message": "Saldo tidak cukup", "balance": 2000, "price": 3000 } }

Idempotency-Key

Untuk POST /orders dan POST /deposits kamu bisa menambah header Idempotency-Key (8 sampai 64 karakter, huruf, angka, -, _). Kalau permintaan diulang dengan key yang sama dalam 24 jam, server mengembalikan hasil pertama tanpa memotong saldo lagi, dengan header Idempotent-Replay: true. Pakai ini supaya aman saat koneksi putus dan kamu mengulang permintaan.

Batas permintaan

Per API key: 60 permintaan per menit untuk GET dan 20 per menit untuk POST. Header X-RateLimit-Limit dan X-RateLimit-Remaining ada di setiap respons. Jika terlampaui, server membalas 429 dengan header Retry-After (detik). Jangan polling status lebih rapat dari 5 detik.

Endpoint

Alur yang disarankan

Order nomor dan OTP

  1. GET /countries lalu GET /services untuk memilih negara, layanan, dan melihat harga.
  2. POST /orders. Saldo langsung dipotong dan kamu menerima number. Nomor berlaku sekitar 20 menit (lihat expires_at).
  3. Pakai nomor itu di aplikasi tujuan, lalu polling GET /orders/{id} tiap 5 detik sampai otp berisi kode.
  4. Jika OTP tidak datang, panggil POST /orders/{id}/cancel. Order yang dibatalkan atau kedaluwarsa dikembalikan saldonya otomatis, hanya sekali.
Setelah OTP masuk, order dianggap selesai dan saldo tidak dikembalikan. Nilai status diteruskan dari penyedia (contoh: waiting, canceled, expired). Anggap order sukses kalau otp tidak null.

Isi saldo

  1. POST /deposits dengan nominal. Jika qr_link berisi gambar (data URI), tampilkan.
  2. Jika qr_link adalah null, panggil GET /deposits/{id}/qr. Server membuka halaman bayar QRIS lalu mengambil screenshot-nya. Selama masih dibuat, respons berstatus 202 dengan qr_pending: true; ulangi tiap 5 detik sampai qr_link terisi. Proses biasanya memakan 10 sampai 60 detik.
  3. Jika qr_link tetap null dan qr_error terisi, buka pay_url di browser untuk membayar lewat halaman pembayaran.
  4. Polling GET /deposits/{id} sampai status menjadi berhasil. Saldo bertambah otomatis satu kali.
Gambar dari /qr adalah screenshot halaman bayar berukuran width x height (420 x 620 piksel), bukan QR polos. Bagian yang berisi QR dimulai dari crop.top sepanjang crop.height piksel. Potong gambarnya sebelum ditampilkan, seperti contoh di bawah. Setelah deposit berhasil, batal, atau kedaluwarsa, endpoint ini membalas 409 deposit_closed.

Menampilkan QR dari screenshot

HTML: potong dengan CSS. Angka 79.29% berasal dari crop.top / (height - crop.height) = 222 / 280.

<img src="DATA_URI_DARI_qr_link" width="300"
     style="aspect-ratio:420/340;object-fit:cover;object-position:50% 79.29%">

Python: potong dengan Pillow.

import base64, io
from PIL import Image

raw = base64.b64decode(qr_link.split(',', 1)[1])
Image.open(io.BytesIO(raw)).crop((0, 222, 420, 562)).save('qr.png')
